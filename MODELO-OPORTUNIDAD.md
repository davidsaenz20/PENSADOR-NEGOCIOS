# MODELO — OPORTUNIDAD

Definición de la estructura conceptual utilizada por PENSADOR-NEGOCIOS para representar una oportunidad de negocio.

---

# 1. PROPÓSITO

Este documento define qué información debe poder almacenar y analizar el sistema cuando descubre una oportunidad.

No es todavía una base de datos ni una estructura técnica.

Es un modelo conceptual.

Su finalidad es evitar que las oportunidades se gestionen únicamente como conversaciones o textos desordenados.

---

# 2. PRINCIPIO FUNDAMENTAL

Una oportunidad no debe representarse únicamente mediante una descripción de negocio.

Debe conservar también:

- de dónde surgió;
- qué problema intenta resolver;
- quién lo sufre;
- qué evidencia existe;
- qué soluciones existen;
- qué diferencia propone;
- qué supuestos contiene;
- qué argumentos existen en contra;
- qué incertidumbres permanecen;
- qué cambios ha sufrido;
- y cuál es su estado actual.

---

# 3. IDENTIFICACIÓN

Cada oportunidad deberá poder identificarse de forma independiente.

Campos conceptuales:

- ID
- nombre provisional
- fecha de creación
- última actualización
- estado
- versión

El nombre puede cambiar durante la evolución.

El ID debe permanecer estable.

---

# 4. ORIGEN

Debe registrarse cómo apareció la oportunidad.

Posibles orígenes:

- exploración libre;
- exploración dirigida;
- idea proporcionada por el usuario;
- problema descubierto;
- investigación;
- combinación de oportunidades;
- evolución de otra oportunidad;
- tendencia;
- cambio tecnológico;
- cambio regulatorio;
- cambio de comportamiento;
- observación del mercado.

También deberá conservarse la oportunidad o hipótesis de origen cuando exista.

---

# 5. PROBLEMA

Debe existir una descripción concreta del problema.

Campos conceptuales:

### Problema

¿Qué ocurre?

### Persona afectada

¿Quién sufre el problema?

### Contexto

¿En qué situación aparece?

### Frecuencia

¿Con qué frecuencia ocurre?

### Intensidad

¿Qué importancia tiene?

### Consecuencia

¿Qué ocurre si no se resuelve?

### Coste

¿Qué coste económico, temporal o de otro tipo genera?

### Frustración

¿Qué dificultad o molestia produce?

---

# 6. CLIENTE

Debe distinguirse entre las diferentes personas implicadas.

Cuando sea posible:

- usuario;
- comprador;
- pagador;
- beneficiario;
- decisor.

No debe asumirse que son la misma persona.

---

# 7. SOLUCIÓN ACTUAL

Debe describirse cómo se resuelve actualmente el problema.

Puede incluir:

- producto;
- servicio;
- profesional;
- herramienta;
- proceso manual;
- software;
- hoja de cálculo;
- marketplace;
- solución interna;
- ninguna solución;
- combinación de varias soluciones.

---

# 8. DEFICIENCIA ACTUAL

Debe identificarse qué problema presentan las soluciones existentes.

Ejemplos:

- demasiado caras;
- demasiado complejas;
- lentas;
- difíciles de utilizar;
- no especializadas;
- mal distribuidas;
- requieren demasiado trabajo manual;
- no atienden un segmento;
- no resuelven el problema completo;
- no funcionan en determinados mercados;
- presentan una experiencia deficiente.

---

# 9. OPORTUNIDAD

Debe describirse por qué podría existir una oportunidad.

La oportunidad puede proceder de:

- problema mal resuelto;
- segmento desatendido;
- solución demasiado cara;
- solución demasiado compleja;
- cambio tecnológico;
- cambio de comportamiento;
- cambio regulatorio;
- nueva distribución;
- combinación de soluciones;
- nuevo modelo económico;
- nueva forma de prestar un servicio.

---

# 10. SOLUCIÓN PROPUESTA

Debe describirse la posible solución.

Debe evitarse confundir esta sección con una especificación técnica completa.

Debe responder principalmente:

¿Qué podríamos hacer para resolver el problema de una forma suficientemente mejor o diferente?

---

# 11. PROPUESTA DE VALOR

Debe explicar:

¿Por qué debería importarle al cliente?

Debe intentar expresar:

- problema;
- beneficio;
- diferenciación;
- resultado esperado.

Debe evitar utilizar únicamente lenguaje de marketing.

---

# 12. HIPÓTESIS

Toda oportunidad debe contener las hipótesis principales que todavía no están demostradas.

Ejemplos:

- existe el problema;
- el problema es suficientemente importante;
- el segmento está dispuesto a cambiar;
- el cliente pagaría;
- la solución puede construirse;
- la distribución es posible;
- el coste de adquisición puede ser razonable;
- existe suficiente mercado.

Cada hipótesis debe poder investigarse o validarse.

---

# 13. EVIDENCIA

La evidencia debe registrar información que apoye o contradiga las hipótesis.

Cada evidencia debería poder clasificarse como:

- favorable;
- desfavorable;
- neutral;
- ambigua.

También debe conservarse la fuente cuando exista.

---

# 14. FUENTES

Cuando se realice investigación externa, deben conservarse las fuentes relevantes.

Una fuente debe permitir conocer:

- qué se ha encontrado;
- dónde;
- cuándo;
- qué hipótesis afecta;
- si apoya o contradice la hipótesis.

No es necesario almacenar toda la información encontrada.

Debe conservarse la información útil para la decisión.

---

# 15. COMPETENCIA

Debe registrarse:

- competidores directos;
- competidores indirectos;
- sustitutos;
- alternativas gratuitas;
- soluciones manuales;
- soluciones internas.

Cuando sea relevante:

- qué ofrecen;
- para quién;
- precio;
- modelo;
- ventajas;
- debilidades;
- distribución;
- antigüedad aproximada.

---

# 16. DIFERENCIACIÓN

Debe responder:

¿Qué hace diferente a esta oportunidad?

La diferenciación puede proceder de:

- producto;
- segmento;
- precio;
- distribución;
- tecnología;
- experiencia;
- especialización;
- automatización;
- modelo de negocio;
- integración;
- velocidad;
- conveniencia;
- combinación.

La diferenciación debe ser concreta.

---

# 17. NOVEDAD

Debe registrar el grado de novedad observado.

Categorías iniciales:

### NUEVO

No se ha encontrado una solución equivalente durante la investigación realizada.

Esto no demuestra que no exista.

### EXISTENTE CON DIFERENCIA

Existen soluciones similares, pero se ha encontrado una diferencia relevante.

### EXISTENTE MAL RESUELTO

El mercado ya ofrece soluciones, pero existe evidencia de deficiencias.

### EXISTENTE / SATURADO

Existen numerosas soluciones similares y no se ha encontrado una diferenciación suficiente.

### INDETERMINADO

No existe suficiente investigación para determinarlo.

---

# 18. MODELO DE NEGOCIO

Debe describirse de forma provisional:

- quién paga;
- qué paga;
- cómo paga;
- frecuencia;
- posible precio;
- modelo recurrente o puntual;
- costes principales.

Estos datos son hipótesis hasta que exista evidencia suficiente.

---

# 19. DISTRIBUCIÓN

Debe registrar cómo podría llegar la solución al cliente.

Posibles canales:

- SEO;
- publicidad;
- ventas directas;
- outbound;
- marketplaces;
- partnerships;
- referidos;
- comunidades;
- contenido;
- redes sociales;
- distribución existente;
- otros.

Debe distinguirse entre:

"existe un canal posible"

y:

"tenemos evidencia de que este canal funciona para este tipo de cliente".

---

# 20. VENTAJAS POTENCIALES

Debe registrarse cualquier posible ventaja competitiva.

Ejemplos:

- especialización;
- datos;
- tecnología;
- automatización;
- distribución;
- comunidad;
- marca;
- conocimiento;
- costes;
- red;
- integración;
- recurrencia.

No debe considerarse ventaja real hasta que exista evidencia.

---

# 21. RIESGOS

Debe registrar los principales riesgos conocidos.

Categorías posibles:

- demanda;
- competencia;
- tecnología;
- regulación;
- adquisición;
- costes;
- operaciones;
- dependencia de plataformas;
- dependencia de terceros;
- escalabilidad;
- comportamiento del cliente.

---

# 22. OBJECIONES

Las objeciones son argumentos concretos contra la oportunidad.

Ejemplos:

- "el cliente puede hacerlo gratis";
- "el mercado es demasiado pequeño";
- "Google ya resuelve esto";
- "el cliente no tiene suficiente urgencia";
- "la adquisición sería demasiado cara";
- "la regulación dificulta el modelo".

Cada objeción debería poder contrastarse.

---

# 23. ATAQUE

Debe conservarse el resultado del intento de destrucción.

Debe incluir:

- argumentos utilizados;
- evidencias encontradas;
- puntos débiles;
- puntos que sobrevivieron;
- puntos que no sobrevivieron;
- conclusión.

---

# 24. EVOLUCIÓN

Una oportunidad debe poder conservar su historial de cambios.

Cada evolución puede registrar:

- versión;
- fecha;
- cambio realizado;
- motivo;
- evidencia que provocó el cambio;
- resultado.

Ejemplo conceptual:

V1
Problema general.

↓

V2
Especialización en un segmento.

↓

V3
Cambio de modelo de negocio.

↓

V4
Nueva solución basada en nueva evidencia.

---

# 25. INCERTIDUMBRES

Debe existir una lista de cuestiones importantes todavía desconocidas.

Ejemplos:

- tamaño real del mercado;
- disposición a pagar;
- dificultad técnica;
- regulación;
- adquisición;
- competencia futura.

Las incertidumbres deben poder priorizarse según su impacto.

---

# 26. PREGUNTAS PENDIENTES

Deben registrarse las preguntas que necesitan respuesta antes de avanzar.

Ejemplos:

- ¿Existe demanda real?
- ¿Quién paga?
- ¿Qué alternativas utilizan?
- ¿Cuánto pagan actualmente?
- ¿Qué competidores existen?
- ¿Podemos diferenciarnos?
- ¿Podemos adquirir clientes?

---

# 27. DECISIONES

Debe conservarse el historial de decisiones.

Ejemplos:

- continuar;
- investigar;
- pivotar;
- pausar;
- comparar;
- descartar;
- convertir en candidata;
- pasar a BASE-PROYECTOS.

Cada decisión debería incluir:

- fecha;
- decisión;
- motivo;
- evidencia relevante.

---

# 28. ESTADO

Una oportunidad puede encontrarse en uno de estos estados:

### DESCUBIERTA

Se ha identificado inicialmente.

### EN INVESTIGACIÓN

Se está recopilando información.

### HIPÓTESIS

Existe una formulación suficientemente concreta.

### EN CONTRASTE

Se están comprobando las hipótesis principales.

### EN ATAQUE

Está siendo sometida a análisis crítico.

### EN EVOLUCIÓN

Se está modificando.

### PAUSADA

Existe interés, pero no se continúa temporalmente.

### DESCARTADA

La evidencia indica que no merece continuar.

### CANDIDATA

Ha superado las principales pruebas iniciales.

### LISTA PARA BASE-PROYECTOS

Está suficientemente madura para estudiar su construcción real.

---

# 29. NIVEL DE CONFIANZA

El sistema puede registrar un nivel cualitativo de confianza.

Valores iniciales:

- muy bajo;
- bajo;
- medio;
- alto;
- muy alto.

La confianza no representa probabilidad matemática de éxito.

Representa la calidad y cantidad de evidencia disponible respecto a las hipótesis principales.

---

# 30. CALIDAD DE LA INVESTIGACIÓN

Debe diferenciarse entre:

### EXPLORACIÓN INICIAL

Pocas fuentes y conocimiento preliminar.

### INVESTIGACIÓN BÁSICA

Principales soluciones y competidores identificados.

### INVESTIGACIÓN PROFUNDA

Hipótesis principales contrastadas desde diferentes perspectivas.

### INVESTIGACIÓN SUFICIENTE

La información disponible permite tomar una decisión razonable para el siguiente paso.

Estas categorías son orientativas y podrán evolucionar.

---

# 31. DECISIÓN ACTUAL

Cada oportunidad debe tener una decisión actual claramente visible.

Ejemplo:

**DECISIÓN:** INVESTIGAR

**MOTIVO:** Existe evidencia del problema y una posible diferenciación, pero todavía no se conoce suficientemente la disposición a pagar.

---

# 32. PRÓXIMO PASO

Cada oportunidad activa debe tener un siguiente paso concreto.

Debe responder:

"¿Qué deberíamos investigar o hacer ahora para reducir la incertidumbre más importante?"

No debe ser simplemente:

"seguir investigando".

Debe ser una acción concreta.

---

# 33. REGLA DE ACTUALIZACIÓN

La información de una oportunidad debe actualizarse cuando aparezca evidencia relevante.

No debe modificarse retroactivamente una hipótesis sin conservar el cambio.

La evolución debe poder reconstruirse.

---

# 34. PRINCIPIO DE HISTORIAL

Las oportunidades no deben perder su historia.

Si una idea cambia, debe conservarse:

- qué era antes;
- qué cambió;
- por qué cambió;
- qué evidencia provocó el cambio.

Esto permitirá aprender de las investigaciones anteriores.

---

# 35. PRINCIPIO DE SEPARACIÓN

Debe distinguirse claramente entre:

PROBLEMA

SOLUCIÓN

OPORTUNIDAD

HIPÓTESIS

EVIDENCIA

DECISIÓN

No deben mezclarse.

# 37. ESTADO DEL MODELO

**Versión:** 0.1

Este modelo no debe considerarse definitivo.

---

# 38. PRINCIPIO FINAL

Una oportunidad no debe considerarse madura porque tenga una descripción atractiva.

Debe considerarse madura cuando conocemos suficientemente:

- qué problema existe;
- quién lo tiene;
- cómo se resuelve;
- qué está mal;
- qué oportunidad existe;
- qué proponemos;
- qué evidencia tenemos;
- qué argumentos existen en contra;
- qué incertidumbres quedan;
- y cuál es el siguiente paso razonable.

El objetivo del modelo es permitir que PENSADOR-NEGOCIOS pueda pensar sobre una oportunidad de forma acumulativa y no empezar desde cero en cada conversación.
